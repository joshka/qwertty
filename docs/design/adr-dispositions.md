# ADR 0001–0018 disposition table

Phase 2 deliverable. Every existing ADR gets its first real review: **affirmed** (the decision
survives independent scrutiny), **revised** (kernel survives, scope or shape changes), or
**superseded** (a design doc replaces it). Reasoning cites evidence, never the ADR itself.
`req` = the maintainer-local requirements record; `FM` = the failure-mode catalog, now
published as [docs/reference/failure-modes.md](../reference/failure-modes.md) (this table's
FM-* ids match the phase-1 catalog the published page evolved from); design docs are siblings
in this directory.

| ADR  | Decision                                                                                                         | Disposition           | Reasoning (independent)                                                                                                                                                                                                                                                                                                                                                            |
| ---- | ---------------------------------------------------------------------------------------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0001 | Async-first, but device layer starts with a small sync core                                                      | **Affirmed**          | Every async-over-blocking failure in FM-A traces to faking async atop blocking reads, while termios/open/size are genuinely synchronous syscalls — a thin sync device core under an honestly-async session is what the evidence supports, and OQ-1's blocking one-shot driver now *needs* that sync core to exist.                                                                 |
| 0002 | `TerminalSession` owns setup/teardown; explicit fallible `leave()`, Drop as fallback                             | **Affirmed**          | Swallowed cleanup errors are a recurring incumbent failure (FM-L8: crossterm#858/#7/#710) and Drop cannot report; an explicit failure-reporting exit path is required by R-SES-2.                                                                                                                                                                                                  |
| 0003 | Runtime-neutral input byte boundary before any runtime dependency                                                | **Affirmed**          | The sans-io core is now the load-bearing architecture (design 04): decoder and correlator must be drivable by Tokio, a blocking one-shot loop, and in-memory tests alike, so the byte boundary below the runtime is structural, not provisional.                                                                                                                                   |
| 0004 | Minimal `InputEvent` classification; everything unknown stays `Undecoded`                                        | **Revised**           | The conservative don't-overclaim instinct is right (FM-P8's inverse: fragments leaking as text, codex#7829), but the event vocabulary itself is the highest-churn surface and gets redesigned wholesale for kitty/mouse/paste/OQ-6 in design 02 — the specific enum shape does not survive.                                                                                        |
| 0005 | UTF-8 scalar decoding chunk-locally in `InputBytes::events`; no cross-read buffering there                       | **Revised**           | Correct-by-evidence for buffering ownership (chunk-local value types can't hide state), but the char-only text payload is contradicted by the IME/compose evidence (FM-P16) and the OQ-6 spike governs the replacement shape.                                                                                                                                                      |
| 0006 | Parse exactly four arrow-key CSIs; everything else undecoded                                                     | **Superseded**        | A four-key parser was scaffolding, not a boundary; R-IN-5 requires full kitty + legacy modifier decoding, and design 02 replaces the piecemeal-escape approach with a total syntax layer plus a semantic layer.                                                                                                                                                                    |
| 0007 | Stateful `InputDecoder` owns cross-read buffering; explicit `finish()`; no ESC-timing guesses                    | **Affirmed**          | Chunk-boundary state loss is one of the most reproduced failure classes in the wild (FM-P1: zellij#4553, notcurses#2852) and ESC disambiguation is timing policy that belongs above the decoder (FM-P7) — both judgments hold under the wider evidence.                                                                                                                            |
| 0008 | Lossless `CsiInput` syntax value preserving all bytes                                                            | **Revised**           | Byte-lossless syntax preservation is the single most load-bearing decoder property (R-IN-2), but CSI-only is not enough — the same treatment must extend to OSC/DCS/APC/PM/SOS (the named "main decoder gap"), which changes the type design (design 02).                                                                                                                          |
| 0009 | CPR command + report parsing as pure types, no live routing                                                      | **Affirmed**          | Pure, device-free report parsers are exactly what a sans-io correlator composes and what ghostty-rs can consume as an encode oracle; the layering survives independent of what sits above it.                                                                                                                                                                                      |
| 0010 | Deterministic first-match extraction preserving all other events                                                 | **Affirmed**          | Preserve-unrelated-input-in-order is the core anti-theft guarantee (FM-Q1/Q6) and a pure matcher is testable without a terminal; this generalizes rather than changes as the correlator grows (design 03).                                                                                                                                                                         |
| 0011 | Tokio session behind default-off feature; no runtime-agnostic trait yet                                          | **Affirmed (recast)** | Traits abstracted over zero-or-one implementations freeze the wrong shape (the ecosystem's own `Backend`-trait churn shows this), but the *reason* it's safe to defer is new: runtime neutrality is delivered by the sans-io core (design 04), not promised by a future trait.                                                                                                     |
| 0012 | Query routing internal to the session; narrow typed public methods; one pending query                            | **Revised**           | Narrow typed methods and no public router survive (consumers want `background_color()`, not a registry — profile evidence), but "one pending query" cannot express the DA1-fenced probe bundle every serious consumer independently invented (R-QRY-4: helix, zellij, notcurses, kitten, codex), so the internal correlator becomes a multi-expectation state machine (design 03). |
| 0013 | Unix-first; platform-neutral types everywhere; `Unsupported` at operation boundary; support claims require tests | **Affirmed**          | "Support is validated behavior, not compilation" is precisely the lesson of the compat clusters (FM-W7, FM-E3), and R-PLAT-1/2 adopted the same posture from the evidence before this review reached the ADR.                                                                                                                                                                      |
| 0014 | Single crate; split only on concrete evidence                                                                    | **Affirmed**          | Ecosystem version-lockstep pain (FM-E1) and the prototype's 17-crate sprawl both argue the same way; the one genuinely separate audience (registry/conformance *tooling*, design 05) gets its split when it exists, which is exactly the rule.                                                                                                                                     |
| 0015 | Pre-1.0 churn allowed but justified; docs/examples/claims move together                                          | **Affirmed**          | rabbitui explicitly prefers honest breakage over freezing `InputEvent` wrong (contract ask), and undocumented contract drift is how incumbents accumulated their doc-mismatch issue clusters (audit theme 8).                                                                                                                                                                      |
| 0016 | Minimal dependencies; integration deps optional/default-off                                                      | **Affirmed**          | Dependency breakage is a top-five incumbent failure cluster (FM-E3, ~30 crossterm titles) and the one-shot profile makes dependency weight a binding adoption constraint (OQ-1 resolution).                                                                                                                                                                                        |
| 0017 | First release = sync core + Tokio session with query contracts; excludes protocol breadth                        | **Superseded**        | The release definition is remade by the Phase 1 P0 surface: a release without styling, alt screen, kitty keyboard, paste, and resize events cannot displace crossterm for any surveyed consumer (substrate-status §5 says so bluntly), so first-publish content is now a Phase 3 build-plan decision against the P0 list.                                                          |
| 0018 | First published version is 0.1.0                                                                                 | **Affirmed**          | No public release history exists, so any higher number would signal maturity that isn't there; the version *number* survives even though the release *content* (0017) does not.                                                                                                                                                                                                    |

## Net effect

Twelve affirmed (two with recast reasoning), four revised, two superseded. The revisions
cluster exactly where Phase 1 predicted churn: the input event vocabulary (0004/0005/0006/0008)
and the query correlator's internal capacity (0012). Nothing in the session-lifecycle,
layering, platform-honesty, or dependency-posture decisions failed scrutiny — the prior
line's judgment was mostly sound at the boundaries and thinnest in protocol breadth, which is
consistent with how it was produced (micro-slices never forced the breadth questions).
